# بازی‌ساز کوچولو | Little Game Maker

یک بازی‌ساز فارسی و آفلاین با Flutter برای طراحی، ویرایش و اجرای بازی‌های کودکانه؛ همراه با موتور Flame/Forge2D برای سکوبازی فیزیکی، Sprite Sheet، ویرایشگر چندلایه با نمایش/پنهان‌سازی لایه‌ها، قوانین ساده رویدادی، نقشه مراحل و دستاوردها.

## امکانات فعلی

- **هزارتو:** تولید مرحله تصادفی با مسیر قابل‌حل، دیوار، گوهر، نقطه شروع و خروجی؛ بررسی بازبودن مسیر پیش از اجرای پیش‌نمایش.
- **سکوبازی:** موتور Flame و Forge2D با گرانش و برخورد واقعی، حرکت پیوسته، پرش و پرش دوم، سکوهای فیزیکی، دوربین دنبال‌کننده با بزرگ‌نمایی مناسب بازی موبایل، دشمن، سکه، جان و نقطه پایان.
- **بازی حافظه:** چیدمان ۱۶ کارت و پیدا کردن ۸ جفت.
- **رانندگی:** سه مسیر، تغییر لاین، موانع متحرک، جایزه‌های قابل‌جمع‌آوری و امتیاز.
- ویرایشگر لمسی با انتخاب ابزار و کشیدن ابزار روی خانه‌ها؛ همراه با واگرد/انجام دوباره تا ۸۰ تغییر، پاک‌کردن سریع صفحه و جداسازی بازترسیم بوم از سایر اجزای رابط برای کاهش بازترسیم‌های غیرضروری. سکوبازی از پنج لایه مستقل (لایه اصلی، پس‌زمینه، زمین و سکو، اشیا و جایزه‌ها، شخصیت‌ها و دشمنان) پشتیبانی می‌کند؛ لایه‌ها برای هر مرحله جداگانه ذخیره می‌شوند.
- ساخت حداکثر ۲۰ مرحله برای هر پروژه، جابه‌جایی میان مراحل، تکثیر و حذف مرحله؛ پس از پایان هر مرحله می‌توان به مرحله بعد رفت.
- پشتیبان‌گیری و انتقال پروژه‌ها با خروجی JSON در کلیپ‌بورد و واردکردن JSON در دستگاه دیگر.
- تصویرسازی برداری اختصاصی برای شخصیت‌ها، موانع، سکه‌ها، گوهرها، سکوها، خودرو و کارت‌های حافظه؛ بدون وابستگی به ایموجی دستگاه یا دریافت تصویر از اینترنت. هشت شخصیت انتخابی سکوبازی با Sprite Sheet اختصاصی چهار فریمی برای حالت ایستادن، دویدن و پریدن متحرک می‌شوند.
- پس‌زمینه‌های نقاشی‌شده با Canvas؛ در سکوبازی ابرها و سه عمق تپه با سرعت‌های متفاوت حرکت می‌کنند (Parallax سبک و کم‌هزینه). انتخاب شخصیت و چهار تم رنگی، صدا و موسیقی تولیدشده درون برنامه.
- ذخیره و ویرایش پروژه‌ها روی دستگاه با `shared_preferences`؛ اجرای بازی‌ها بدون اینترنت.
- نرمال‌سازی داده‌های ذخیره‌شده قدیمی یا ناقص برای جلوگیری از خراب‌شدن پروژه‌ها؛ پروژه‌های تک‌مرحله‌ای قدیمی به‌صورت خودکار به قالب چندمرحله‌ای تبدیل می‌شوند.

## اجرای پروژه در محیط توسعه

Flutter 3.47 یا جدیدتر، Dart 3.12 یا جدیدتر و Android SDK/NDK را نصب کن، سپس در ریشه پروژه اجرا کن:

```bash
flutter create . --platforms=android --org com.littlegamemaker --project-name little_game_maker
flutter pub get
flutter test
flutter analyze
flutter run
```

دستور `flutter create` پوشه‌های پلتفرم اندروید را برای این سورس تولید می‌کند؛ این پوشه‌ها در ZIP سورس نگهداری نشده‌اند و Workflow گیت‌هاب نیز همین کار را پیش از ساخت انجام می‌دهد.

## ساخت APK امضاشده با GitHub Actions

Workflow با نام **Android Release APK** در این مسیر قرار دارد:

`.github/workflows/android-release.yml`

Workflow با هر Push به شاخه `main` و همچنین با اجرای دستی (`workflow_dispatch`) اجرا می‌شود. چهار Secret زیر باید در تنظیمات مخزن، بخش **Settings → Secrets and variables → Actions** ثبت شده باشند:

- `LITTLEGAMEMAKER_KEYSTORE_BASE64`
- `LITTLEGAMEMAKER_KEY_PASSWORD`
- `LITTLEGAMEMAKER_STORE_PASSWORD`
- `LITTLEGAMEMAKER_KEY_ALIAS`

`LITTLEGAMEMAKER_KEYSTORE_BASE64` محتوای فایل keystore به‌صورت Base64 است. سه مقدار دیگر رمزها و alias همان keystore هستند. فایل keystore و رمزهای آن را داخل مخزن Git قرار نده.

پس از موفقیت Workflow، فایل APK را از بخش **Actions → اجرای موفق → Artifacts → little-game-maker-release-apk** دریافت کن.

## نکات انتشار

- برای انتشار به‌روزرسانی، `version` در `pubspec.yaml` را افزایش بده؛ قالب آن `version: major.minor.patch+buildNumber` است.
- برای انتشار عمومی، کلید امضای ثابت و امن خودت را نگه دار و در نسخه‌های بعدی از همان کلید استفاده کن؛ تغییر کلید ممکن است مانع نصب به‌روزرسانی روی نسخه قبلی شود.
- این مخزن شامل سورس است و فایل APK در زمان اجرای Workflow ساخته می‌شود.

## قابلیت‌های نسخه 2.2.0+8

- نمایش/پنهان‌سازی مستقل هر لایه در هر مرحله؛ وضعیت دیداری لایه‌ها در JSON ذخیره می‌شود و با جابه‌جایی یا حذف لایه، وضعیت نمایش نیز همراه آن حرکت می‌کند.
- نقشه مراحل با قفل‌بودن مرحله بعد تا تکمیل مرحله قبلی؛ تکمیل مرحله‌ها به‌صورت محلی روی دستگاه ذخیره می‌شود.
- سیستم دستاوردهای محلی: ساخت اولین بازی، پیروزی اول، تکمیل مرحله سوم و ساخت هر چهار نوع بازی.
- پنل قوانین ساده رویدادی در ویرایشگر: تعیین امتیاز اضافه برای جمع‌آوری سکه و فعال‌کردن جان اضافه هنگام گرفتن سکه. این قوانین در هزارتو، رانندگی و سکوبازی فیزیکی اعمال می‌شوند.
- رفع اشکال همگام‌سازی پروژه: ویرایش مستقیم خانه‌های بازی‌های غیرسکوبازی هنگام ذخیره دیگر با داده لایه پایه بازنویسی نمی‌شود.
- رفع ترکیب نشانگر پاک‌کن لایه‌ها هنگام بارگذاری پروژه و حفظ وضعیت لایه‌های مخفی در ذخیره/بازیابی.
- آزمون‌های مدل برای دید/پنهان‌سازی لایه‌ها، جابه‌جایی لایه همراه وضعیت دید، قوانین بازی و همگام‌سازی خانه‌ها اضافه شده‌اند.

## قابلیت‌های نسخه 2.1.0+7

- **موتور سکوبازی:** Flame 1.38.2 و flame_forge2d 0.20.0؛ Forge2D برای شبیه‌سازی گرانش، جسم پویا، برخورد با سکوها و دیواره‌ها.
- **فیزیک بازیکن:** حرکت پیوسته با شتاب و کاهش سرعت نرم و بزرگ‌نمایی دوربین تنظیم‌شده برای اندازه مناسب شخصیت‌ها، پرش با بافر ورودی، مهلت کوتاه پرش پس از لبه سکو (Coyote Time)، پرش دوم، محدودیت محیط، بازگشت پس از برخورد با دشمن یا سقوط و چشمک‌زدن هنگام آسیب.
- **انیمیشن:** فایل `assets/images/fox_animations.png` شامل هشت مجموعه شخصیت است؛ هر مجموعه سه ردیف (ایستادن، دویدن و پرش) و هر ردیف چهار فریم دارد.
- **لایه‌ها:** هر مرحله می‌تواند حداکثر پنج لایه مستقل داشته باشد. امکان افزودن، انتخاب، حذف لایه انتخاب‌شده و جابه‌جایی ترتیب لایه‌ها فراهم است؛ پاک‌کن در لایه بالاتر می‌تواند محتوای زیرین را در همان خانه پنهان کند.
- **سازگاری:** پروژه‌های نسخه‌های قبلی هنگام خواندن به ساختار یک‌لایه‌ای تبدیل می‌شوند و می‌توانند در نسخه جدید ویرایش شوند.
- **وابستگی‌ها:** Flame و Forge2D برای اجرای سکوبازی استفاده می‌شوند؛ سه بازی دیگر همچنان از پیاده‌سازی فعلی Flutter استفاده می‌کنند.
